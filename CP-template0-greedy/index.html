七、贪心

1. 区间问题

1.1 区间合并

题型特征

给若干区间，要求把所有有交集的区间合并，求合并后的区间个数或合并后的结果。

贪心策略

按左端点从小到大排序。

核心思路

维护当前合并区间的右端点 ed：

  • 若新区间左端点 l <= ed，说明有交集，更新 ed = max(ed, r)
  • 否则说明出现新区间，答案加一，并重置 ed

1.2 区间选点

题型特征

给若干闭区间，选尽量少的点，使每个区间至少包含一个点。

贪心策略

按右端点从小到大排序，优先选当前区间的右端点。

核心思路

因为右端点越小，越能兼顾后面的区间。
所以每次都选当前最早结束区间的右端点。

1.3 最大不相交区间数量

题型特征

给若干区间，要求选出尽可能多的区间，使它们两两不相交。

贪心策略

按右端点从小到大排序。

核心思路

这题和“区间选点”本质一样。
每次优先选右端点最小的区间，这样能给后面留下最多空间。

模板

1.4 区间分组

题型特征

给若干区间，要求分成尽量少的组，使每组内部区间两两不相交。

贪心策略

按左端点从小到大排序，再用小根堆维护每组当前最小的右端点。

核心思路

  • 堆顶表示当前最早结束的那一组
  • 如果当前区间左端点 l <= heap.top()，说明和最早结束的那组也有冲突，只能新开一组
  • 否则可以放进这组，弹出旧右端点，加入新区间右端点

1.5 区间覆盖

题型特征

给定目标区间 [st, ed]，从若干区间中选尽量少的区间把它完全覆盖。

贪心策略

按左端点从小到大排序，每次在所有能接上当前 st 的区间中，选右端点最远的那个。

核心思路

设当前要覆盖到的位置是 st：

  • 找所有满足 l <= st 的区间
  • 在这些区间中选 r 最大的
  • 这样一步尽量向右扩展最多
  • 若最大 r 仍然小于 st，说明无法覆盖

2. 反悔贪心

适用场景

有一批决策按顺序出现：

  • 当前先贪心选一个
  • 以后发现有更优选择时，允许撤销之前较差的选择
  • 典型维护结构通常是优先队列、平衡树

经典思路

用一个堆维护“当前已选方案中最差的那个”。 若新来的更优，就把最差的弹掉，再换成当前更优的。

做法理解

最小堆里维护“之前买入的股价”。 若当前价格 x 比堆顶更大，说明把之前更低价买的那股放到今天卖更优：

  • 收益增加 x - pq.top()
  • 弹出旧买入价
  • 插入当前价，表示这次卖出后仍可视为“在今天重新买回一股”，以便后续继续反悔
