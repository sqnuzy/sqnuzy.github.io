408计组｜Cache：映射、替换算法与写策略

学习笔记 / 408 / 计算机组成原理 #408 #计算机组成原理 #存储系统 #Cache
← 复习笔记

Cache 利用程序的局部性保存主存数据副本。本篇集中整理命中率、地址映射、替换算法和写策略，并用例题区分容易混淆的计算。

SRAM = 静态随机存取存储器（静态RAM）

DRAM = 动态随机存取存储器（动态RAM）

Cache的设计基于程序访问的局部性原理，包括时间局部性和空间

基本原理与局部性

Cache（高速缓冲存储器）保存部分主存数据的副本，缓和 CPU 与主存的速度差异。

局部性 含义 典型例子
时间局部性 刚访问过的信息，不久后可能再次访问 循环中的指令、反复使用的变量
空间局部性 刚访问过的地址，其附近地址可能很快被访问 顺序访问数组、顺序执行指令

主存向 Cache 调入数据以块为单位，Cache 中的块也称为行。同一系统中，两者对应的数据块大小相等；CPU 一次访问其中的字节或字，不等于每次使用整块。

命中率与平均访问时间

设命中率为 \(H\)，缺失率为 \(M\)，访问一次 Cache、主存的时间分别为 \(t_c\)、\(t_m\)。

\(H=\frac{\text{命中次数}}{\text{总访问次数}},\qquad M=1-H\)

访问方式 命中耗时 未命中耗时 平均访问时间
先查 Cache，未命中再查主存 \(t_c\) \(t_c+t_m\) \(t=Ht_c+(1-H)(t_c+t_m)=t_c+Mt_m\)
同时访问 Cache 与主存，命中则停止主存访问 \(t_c\) \(t_m\) \(t=Ht_c+(1-H)t_m\)

计算前先看题目的访问方式，以及是否另计块传输、回写等时间，不能混用公式。

分块与地址划分

以下按字节编址，容量和块大小均按题中二进制单位计算。

设块大小为 \(B\) 字节，主存地址为 \(A\)：

\(\text{主存块号}=\left\lfloor\frac{A}{B}\right\rfloor,\qquad \text{块内地址}=A\bmod B\)

  • 块内地址位数为 \(b=\log_2 B\)。
  • 主存地址共 \(n\) 位，则主存块号占 \(n-b\) 位。
  • Cache 数据容量为 \(C\) 字节，则 Cache 行数为 \(L=C/B\)。

例如：主存为 \(4\,\mathrm{MB}=2^{22}\,\mathrm{B}\)，块大小为 \(1\,\mathrm{KB}=2^{10}\,\mathrm{B}\)。

  • 主存地址为 \(22\) 位，拆成 \(12\) 位主存块号和 \(10\) 位块内地址。
  • 主存共 \(2^{12}=4096\) 块；若 Cache 为 \(8\,\mathrm{KB}\)，则共有 \(8\) 行。

三种映射方式

设待访问的主存块号为 \(j\)，Cache 共 \(L\) 行。

映射方式 主存块可放的位置 地址结构 未命中时的替换范围
全相联映射 任意 Cache 行 标记 + 块内地址 Cache 满后，在所有行中选择
直接映射 唯一指定行：\(i=j\bmod L\) 标记 + 行号 + 块内地址 指定行已被其他有效块占用时，直接替换
组相联映射 指定组内的任意行 标记 + 组号 + 块内地址 指定组满后，仅在该组中选择

对于 \(r\) 路组相联：

\(G=\frac{L}{r},\qquad \text{组号}=j\bmod G\)

其中 \(G\) 是组数，\(r\) 是每组的行数。若 \(G=2^s\)，则组号占 \(s\) 位，标记占 \(n-s-b\) 位。

“2 路”表示每组 2 行，不表示总共 2 组。 主存地址中没有额外的“组内行号”字段，组内通过比较标记找到目标行。

命中判断

先按行号或组号确定查找范围，再比较标记；必须满足有效位为 \(1\) 且标记匹配，才算命中，最后用块内地址定位数据。

  • 全相联：比较所有行的标记。
  • 直接映射：只检查指定行。
  • 组相联：比较指定组内各行的标记。

地址划分例题

主存 \(256\,\mathrm{MB}=2^{28}\,\mathrm{B}\)，按字节编址；Cache 共 \(8\) 行，每行 \(64\,\mathrm{B}=2^6\,\mathrm{B}\)。

主存地址共 \(28\) 位，块内地址占 \(6\) 位，Cache 数据区容量为 \(8\times64=512\,\mathrm{B}\)。

映射方式 标记位数 行号或组号位数 块内地址位数
全相联 \(22\) \(0\) \(6\)
直接映射（由同一组参数推得） \(19\) \(3\) \(6\)
2 路组相联 \(20\) \(2\)，因为 \(8/2=4\) 组 \(6\)

以 2 路组相联为例，主存块号的末两位为 \(01\)，因此属于第 \(1\) 组，可放入 Cache 第 \(2\) 或第 \(3\) 行。块内地址 \(001110_2\) 表示偏移量为 \(14\,\mathrm{B}\)（从 \(0\) 开始编号）。

这里的 \(512\,\mathrm{B}\) 仅指数据区；计算 Cache 总存储容量时，还需按题意计入标记、有效位及其他控制信息。

四种替换算法

替换算法用于在允许放置的范围内选出要淘汰的块；有空闲行时先填入，不需要淘汰已有块。

LRU：Least Recently Used，中文常译作 最近最少使用（更准确说：最近最久未使用）。

LFU：Least Frequently Used，中文常译作 最不经常使用（访问频率最低）。

算法 淘汰谁 记忆要点
RAND：随机替换 随机选一块 实现简单，不利用访问历史，结果不固定
FIFO：先进先出 最早调入的块 看装入先后；命中不改变先后顺序
LRU：近期最少使用 最久没有被访问的块 看最近访问顺序；命中要更新顺序
LFU：最不经常使用 访问次数最少的块 看频次；可能保留过去热门、现在不用的块

LRU 看“多久没用”，LFU 看“用了几次”，两者不能混淆。不同算法的效果取决于访问序列，不能认为 LRU 在所有序列上都优于 LFU。

LRU 的排序计数法

采用排序计数法：\(0\) 表示最近使用，数值越大表示越久未使用；需要替换时淘汰最大值。

  1. 命中：该行计数清零，原先计数比它小的有效行加 \(1\)，其他不变。
  2. 未命中且有空闲行：新行计数置 \(0\)，其他已占用行的计数加 \(1\)。
  3. 未命中且无空闲行：淘汰计数最大的行，新行计数置 \(0\)，其他行的计数加 \(1\)。

组相联时，上述维护和比较只在所属组内进行。LFU 则维护访问频次、淘汰最小值；频次相同时按题目指定的规则选择。

访问序列例题

条件：Cache 初始为空，共 \(4\) 行，采用全相联映射。依次访问主存块：

\(1,2,3,4,1,2,5,1,2,3,4,5\)

算法 命中次数 未命中次数 替换次数 命中率
RAND，按本例指定选择 \(5\) \(7\) \(3\) \(5/12\)
FIFO \(2\) \(10\) \(6\) \(1/6\)
LRU \(4\) \(8\) \(4\) \(1/3\)
LFU，同频时选较小行号 \(5\) \(7\) \(3\) \(5/12\)

前 \(4\) 次都是未命中，但只填入空闲行，没有发生替换。因此未命中次数不等于替换次数。

LRU 的 \(4\) 次命中发生在第 \(5\)、\(6\)、\(8\)、\(9\) 次访问；发生替换时，淘汰顺序依次为块 \(3,4,5,1\)。

本例首次填充时按 Cache 行号从小到大放入；RAND 在三次替换时依次淘汰块 \(3,4,1\)。LFU 新装入行的频次从 \(0\) 开始，命中加 \(1\)，同频时优先淘汰行号较小的块。RAND 和 LFU 在其他选择规则下可能得到不同结果。

Cache 写策略

以下按 Cache—主存两级模型理解。写策略分两个问题：写命中时，何时更新主存；写未命中时，要不要把目标块调入 Cache。

写命中：全写法与回写法

策略 怎么写 特点
全写法 / 写直达（Write-through） 更新 Cache，同时向主存发送写入 主存写操作较多，常配写缓冲
回写法 / 写回法（Write-back） 先只更新 Cache，并置脏位；脏块被替换时再写回主存 可减少对同一块反复写主存的次数，需要维护脏位

回写法为每行设置脏位（修改位）\(D\)：

  • \(D=0\)：该行未被写脏，替换时不必回写。
  • \(D=1\)：该行已被修改，主存可能尚未更新，替换前需要回写。
  • 从主存装入新块时，脏位置 \(0\)；随后按回写策略修改该块时，脏位置 \(1\)。

有效位 \(V\) 判断“这一行是否有效”，脏位 \(D\) 判断“替换时是否需要回写”。 即使当前操作是读未命中，若淘汰了脏块，也需要先回写旧块，再读取新块。

写未命中：写分配与非写分配

策略 怎么处理 是否把目标块调入 Cache
写分配（Write-allocate） 先调入目标主存块，再修改 Cache 中的数据；主存何时更新由全写或回写策略决定 是
非写分配 / 不按写分配（No-write-allocate） 直接写主存，不为本次写操作装入目标块 否

两者决定的是写未命中时是否装块，与写命中时的更新方式是两个可组合的选择。

常见搭配

搭配 写命中 写未命中
全写法 + 非写分配 更新 Cache，并向主存写入 直接写主存，不调入目标块
回写法 + 写分配 只更新 Cache，置 \(D=1\) 调入目标块后修改，置 \(D=1\)；若需淘汰脏块，先回写旧块

这是常见搭配，并非强制绑定；做题时分别按题设判断。

写缓冲

全写法常在 Cache 与主存之间设置写缓冲：先暂存待写的地址和数据，让 CPU 继续执行，由缓冲向主存完成写入；缓冲满时仍可能等待。

地址划分

做题前，先区分：题目问的是“编号是多少”，还是“需要多少位”。

以下默认按字节编址，相关容量和数量为 \(2\) 的整数次幂。

  1. Cache：根据访问地址，求块号、组号、Tag 和偏移。

    设访问地址为 \(A\)，每块大小为 \(B\) 字节，Cache 共有 \(S\) 组。

    先确定组数：

    \(\text{Cache总行数}=\frac{\text{Cache数据容量}}{\text{每块大小}}\)

    映射方式 Cache 组数 \(S\)
    直接映射 Cache 总行数
    \(E\) 路组相联 Cache 总行数 ÷ \(E\)
    全相联 \(1\)

    再做两次除法：

    运算 商 余数
    访问地址 ÷ 块大小 主存块号 \(q\) 块内偏移
    主存块号 ÷ Cache 组数 Tag 值 Cache 组号

    对应公式为：

    \(q=\lfloor A/B\rfloor,\qquad \text{块内偏移}=A\bmod B\)

    \(\text{Tag值}=\lfloor q/S\rfloor,\qquad \text{组号}=q\bmod S\)

    直接映射时，组号就是 Cache 行号。

    例如：地址为 \(2593\)，块大小为 \(32\,\mathrm{B}\)，共 \(16\) 组。

    \(2593=32\times81+1\)

    得到：主存块号为 \(81\)，块内偏移为 \(1\)。

    \(81=16\times5+1\)

    得到：Tag 值为 \(5\)，Cache 组号为 \(1\)。

    如果题目问字段位数：

    \(\text{偏移位数}=\log_2 B\)

    \(\text{组号位数}=\log_2 S\)

    \(\text{Tag位数}=\text{主存地址位数}-\text{组号位数}-\text{偏移位数}\)

    注意：Tag 值和 Tag 位数是两个问题。

  2. 分页：根据页数、物理块数和页大小，求地址位数。

    设逻辑空间有 \(N\) 页，物理空间有 \(F\) 个物理块，每页大小为 \(P\) 字节。分页中的物理块也称页框，大小与页相同。

    所求字段 计算方法
    逻辑页号位数 \(\log_2 N\)
    物理块号位数 \(\log_2 F\)
    页内偏移位数 \(\log_2 P\)
    逻辑地址总位数 页号位数＋页内偏移位数
    物理地址总位数 物理块号位数＋页内偏移位数

    例如：逻辑空间 \(8\) 页，物理空间 \(32\) 块，每页 \(1024\,\mathrm{B}\)。

    \(\text{逻辑地址位数}=\log_2 8+\log_2 1024=3+10=13\)

    \(\text{物理地址位数}=\log_2 32+\log_2 1024=5+10=15\)

    逻辑地址转换为物理地址时，页内偏移不变，逻辑页号通过页表转换为物理块号。物理块号需要查页表，不能像 Cache 组号那样直接取余。

按字编址时，计算偏移或进行地址除法，要把块大小、页大小换成所包含的字数。另外，Cache 的主存块与分页的页框是不同层次的划分，大小分别按题设确定。
